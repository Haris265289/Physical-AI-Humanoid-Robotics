# Robot Modeling with URDF

This chapter covers the Unified Robot Description Format (URDF) and how to model humanoid robots for use with ROS 2. URDF is essential for simulating, visualizing, and controlling robots in ROS-based systems.

## What is URDF?

URDF (Unified Robot Description Format) is an XML format used to model robot geometry, kinematics, and dynamics in ROS. It allows you to describe a robot in terms of its links (rigid parts) and joints (connections between links). URDF is fundamental to robot simulation, visualization, and control in ROS-based systems.

### Purpose of URDF in Robotics

URDF serves several critical functions in robotics development:

1. **Robot Description**: Provides a complete description of a robot's physical structure, including dimensions, mass, and inertial properties
2. **Kinematic Chain Definition**: Defines how different parts of the robot are connected and how they move relative to each other
3. **Simulation Preparation**: Enables accurate physics simulation in environments like Gazebo
4. **Visualization**: Allows for 3D visualization of the robot in tools like RViz
5. **Collision Detection**: Provides collision geometry for planning and safety systems

### URDF in Humanoid Robotics

In humanoid robotics, URDF is particularly important because:

- **Complex Kinematics**: Humanoid robots have complex kinematic chains with multiple degrees of freedom
- **Symmetry**: Often require symmetric descriptions for left/right limbs
- **Multiple End Effectors**: Need to define hands, feet, and other interaction points
- **Sensor Integration**: Must include mounting points for cameras, IMUs, and other sensors
- **Actuator Specifications**: Need to define joint limits and dynamics for realistic simulation

## URDF Structure for Humanoid Robots

A humanoid robot URDF typically includes:

### Links
Links represent rigid bodies in the robot. For a humanoid robot, these might include:
- Torso/Body
- Head
- Upper and lower arms (left and right)
- Upper and lower legs (left and right)
- Hands and feet

Each link contains:
- **Visual**: How the link appears in visualization tools
- **Collision**: How the link interacts in physics simulation
- **Inertial**: Mass, center of mass, and inertia properties

### Joints
Joints connect links and define their relative motion. Common joint types in humanoid robots:
- **Revolute**: Rotational joints with limited range (e.g., elbow, knee)
- **Continuous**: Rotational joints without limits (e.g., shoulder, hip)
- **Fixed**: Rigid connections (e.g., sensor mounts)

### Transmissions
Transmissions define how actuators connect to joints, including:
- Hardware interface type
- Actuator parameters
- Joint-actuator mapping

### Materials
Visual appearance properties like color and texture for rendering.

## Basic URDF Example

Here's a simple URDF structure for a basic humanoid robot:

```xml
<?xml version="1.0"?>
<robot name="simple_humanoid">
  <!-- Base link -->
  <link name="base_link">
    <inertial>
      <mass value="1.0"/>
      <origin xyz="0 0 0"/>
      <inertia ixx="0.01" ixy="0.0" ixz="0.0" iyy="0.01" iyz="0.0" izz="0.01"/>
    </inertial>
    <visual>
      <origin xyz="0 0 0"/>
      <geometry>
        <box size="0.2 0.1 0.1"/>
      </geometry>
      <material name="blue">
        <color rgba="0 0 1 1"/>
      </material>
    </visual>
    <collision>
      <origin xyz="0 0 0"/>
      <geometry>
        <box size="0.2 0.1 0.1"/>
      </geometry>
    </collision>
  </link>

  <!-- Head link -->
  <link name="head">
    <inertial>
      <mass value="0.5"/>
      <origin xyz="0 0 0"/>
      <inertia ixx="0.005" ixy="0.0" ixz="0.0" iyy="0.005" iyz="0.0" izz="0.005"/>
    </inertial>
    <visual>
      <origin xyz="0 0 0"/>
      <geometry>
        <sphere radius="0.05"/>
      </geometry>
      <material name="white">
        <color rgba="1 1 1 1"/>
      </material>
    </visual>
    <collision>
      <origin xyz="0 0 0"/>
      <geometry>
        <sphere radius="0.05"/>
      </geometry>
    </collision>
  </link>

  <!-- Joint connecting torso to head -->
  <joint name="torso_head_joint" type="revolute">
    <parent link="base_link"/>
    <child link="head"/>
    <origin xyz="0.0 0.0 0.1"/>
    <axis xyz="0 1 0"/>
    <limit lower="-0.5" upper="0.5" effort="10.0" velocity="1.0"/>
  </joint>
</robot>
```

This example shows the basic structure of a URDF file with one link (base_link), one additional link (head), and one joint connecting them. In a real humanoid robot, you would have many more links and joints to represent the complete body structure.

## Defining Links, Joints, and Sensors in URDF

### Links in Detail

A link in URDF represents a rigid body and contains several important elements:

#### Inertial Properties
The `<inertial>` element defines the physical properties of the link for dynamics simulation:

```xml
<inertial>
  <mass value="1.0"/>
  <origin xyz="0 0 0" rpy="0 0 0"/>
  <inertia ixx="0.01" ixy="0.0" ixz="0.0"
           iyy="0.01" iyz="0.0" izz="0.01"/>
</inertial>
```

- **mass**: Mass of the link in kilograms
- **origin**: Center of mass location and orientation
- **inertia**: Moments and products of inertia (3x3 matrix, only 6 independent values)

#### Visual Properties
The `<visual>` element defines how the link appears in visualization:

```xml
<visual>
  <origin xyz="0 0 0" rpy="0 0 0"/>
  <geometry>
    <box size="0.1 0.1 0.1"/>
    <!-- Other options: <sphere radius="0.1"/>, <cylinder radius="0.1" length="0.2"/> -->
  </geometry>
  <material name="red">
    <color rgba="1 0 0 1"/>
  </material>
</visual>
```

#### Collision Properties
The `<collision>` element defines how the link interacts in collision detection:

```xml
<collision>
  <origin xyz="0 0 0" rpy="0 0 0"/>
  <geometry>
    <box size="0.1 0.1 0.1"/>
  </geometry>
</collision>
```

### Joints in Detail

Joints define the relationship between links and how they can move relative to each other:

#### Joint Types
- **fixed**: No movement allowed (rigid connection)
- **revolute**: Rotational movement with limits (like a hinge)
- **continuous**: Rotational movement without limits (like a wheel)
- **prismatic**: Linear sliding movement with limits
- **floating**: 6DOF movement (rarely used)
- **planar**: Movement in a plane (rarely used)

#### Joint Definition Example
```xml
<joint name="shoulder_joint" type="revolute">
  <parent link="torso"/>
  <child link="upper_arm"/>
  <origin xyz="0.2 0.1 0.0" rpy="0 0 0"/>
  <axis xyz="0 1 0"/>
  <limit lower="-1.57" upper="1.57" effort="100.0" velocity="1.0"/>
  <dynamics damping="0.5" friction="0.1"/>
</joint>
```

- **origin**: Position and orientation of the joint relative to the parent link
- **axis**: Axis of rotation/translation (normalized vector)
- **limit**: Joint limits (for revolute/prismatic joints)
- **dynamics**: Physical properties like damping and friction

### Sensors in URDF

Sensors are defined using the `<sensor>` tag in URDF (in newer versions of URDF). Here's how to define different types of sensors:

#### Camera Sensor Example
```xml
<sensor name="camera" type="camera">
  <origin xyz="0.1 0 0.1" rpy="0 0 0"/>
  <parent link="head"/>
  <camera name="my_camera">
    <horizontal_fov>1.047</horizontal_fov>
    <image>
      <width>640</width>
      <height>480</height>
      <format>R8G8B8</format>
    </image>
    <clip>
      <near>0.1</near>
      <far>10.0</far>
    </clip>
  </camera>
</sensor>
```

#### IMU Sensor Example
```xml
<sensor name="imu" type="imu">
  <origin xyz="0 0 0" rpy="0 0 0"/>
  <parent link="torso"/>
  <imu>
    <angular_velocity>
      <x>
        <noise type="gaussian">
          <mean>0.0</mean>
          <stddev>0.001</stddev>
        </noise>
      </x>
      <y>...</y>
      <z>...</z>
    </angular_velocity>
    <linear_acceleration>
      <x>...</x>
      <y>...</y>
      <z>...</z>
    </linear_acceleration>
  </imu>
</sensor>
```

## Integrating URDF Models with ROS 2 Simulations

Once you have a URDF model of your robot, you need to integrate it with ROS 2 simulation environments. This section covers the key aspects of integrating URDF models with ROS 2 simulations.

### Robot State Publisher

The Robot State Publisher is a ROS 2 node that reads a URDF and uses TF2 to publish the state of the robot's joints. This is essential for visualizing the robot in RViz and for simulation.

To launch the robot state publisher with your URDF:

```xml
<launch>
  <!-- Load the URDF into the parameter server -->
  <param name="robot_description" value="$(find-pkg-share my_robot_description)/urdf/my_robot.urdf"/>

  <!-- Launch the robot state publisher -->
  <node pkg="robot_state_publisher" exec="robot_state_publisher" name="robot_state_publisher">
    <param name="robot_description" value="$(var robot_description)"/>
  </node>
</launch>
```

### Joint State Publisher

For visualization purposes, you often need to publish joint states. The joint state publisher can publish static joint positions or allow interactive control:

```xml
<!-- For static poses -->
<node pkg="joint_state_publisher" exec="joint_state_publisher" name="joint_state_publisher">
  <param name="use_gui" value="false"/>
</node>

<!-- For interactive control -->
<node pkg="joint_state_publisher_gui" exec="joint_state_publisher_gui" name="joint_state_publisher_gui">
  <param name="use_gui" value="true"/>
</node>
```

### Launching with Gazebo Simulation

To use your URDF in Gazebo simulation, you need to spawn the robot model in the simulation environment:

```xml
<launch>
  <!-- Launch Gazebo -->
  <include file="$(find-pkg-share gazebo_ros)/launch/gazebo.launch.py"/>

  <!-- Spawn the robot in Gazebo -->
  <node pkg="gazebo_ros" exec="spawn_entity.py" name="spawn_robot" output="screen">
    <param name="entity" value="my_robot"/>
    <param name="topic" value="robot_description"/>
    <param name="x" value="0"/>
    <param name="y" value="0"/>
    <param name="z" value="1"/>
  </node>
</launch>
```

### Adding Gazebo-Specific Elements to URDF

To make your robot work properly in Gazebo, you may need to add Gazebo-specific elements to your URDF:

```xml
<!-- Include Gazebo plugins -->
<gazebo>
  <plugin name="gazebo_ros_control" filename="libgazebo_ros_control.so">
    <parameters>$(find-pkg-share my_robot_hardware)/config/my_robot_control.yaml</parameters>
  </plugin>
</gazebo>

<!-- Define colors for Gazebo visualization -->
<gazebo reference="link_name">
  <material>Gazebo/Blue</material>
</gazebo>

<!-- Add sensors that are specific to Gazebo -->
<gazebo reference="camera_link">
  <sensor type="camera" name="camera1">
    <update_rate>30.0</update_rate>
    <camera name="head">
      <horizontal_fov>1.3962634</horizontal_fov>
      <image>
        <width>800</width>
        <height>800</height>
        <format>R8G8B8</format>
      </image>
      <clip>
        <near>0.02</near>
        <far>300</far>
      </clip>
    </camera>
    <plugin name="camera_controller" filename="libgazebo_ros_camera.so">
      <frame_name>camera_link</frame_name>
    </plugin>
  </sensor>
</gazebo>
```

### Xacro for Complex URDFs

For complex humanoid robots, you'll likely want to use Xacro (XML Macros) to make your URDF more maintainable:

```xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro" name="humanoid_robot">

  <!-- Define properties -->
  <xacro:property name="M_PI" value="3.1415926535897931" />
  <xacro:property name="base_width" value="0.3" />
  <xacro:property name="base_length" value="0.3" />
  <xacro:property name="base_height" value="0.2" />

  <!-- Define a macro for a simple link -->
  <xacro:macro name="simple_link" params="name xyz_origin rpy_origin mass *geometry">
    <link name="${name}">
      <inertial>
        <mass value="${mass}"/>
        <origin xyz="${xyz_origin}" rpy="${rpy_origin}"/>
        <inertia ixx="0.01" ixy="0" ixz="0" iyy="0.01" iyz="0" izz="0.01"/>
      </inertial>
      <visual>
        <origin xyz="${xyz_origin}" rpy="${rpy_origin}"/>
        <xacro:insert_block name="geometry"/>
        <material name="light_grey">
          <color rgba="0.7 0.7 0.7 1.0"/>
        </material>
      </visual>
      <collision>
        <origin xyz="${xyz_origin}" rpy="${rpy_origin}"/>
        <xacro:insert_block name="geometry"/>
      </collision>
    </link>
  </xacro:macro>

  <!-- Use the macro to create a link -->
  <xacro:simple_link name="base_link" xyz_origin="0 0 0" rpy_origin="0 0 0" mass="1.0">
    <geometry>
      <box size="${base_width} ${base_length} ${base_height}"/>
    </geometry>
  </xacro:simple_link>

</robot>
```

### Best Practices for URDF in Humanoid Robotics

1. **Proper Mass Properties**: Accurate mass and inertia properties are crucial for realistic simulation
2. **Joint Limits**: Always specify realistic joint limits to prevent damage in simulation
3. **Collision vs Visual**: Use simple geometries for collision to improve performance
4. **Frame Naming**: Use consistent and descriptive frame names
5. **Mounting Points**: Plan for sensor and attachment points from the beginning
6. **Symmetry**: Use Xacro macros to handle symmetric parts (left/right limbs)
7. **Validation**: Always validate your URDF with tools like `check_urdf`

### Visualizing Your Robot

Once your URDF is integrated with ROS 2, you can visualize it in RViz:

1. Launch your robot state publisher
2. Launch RViz
3. Add a RobotModel display
4. Set the Robot Description parameter to "robot_description"
5. Set Fixed Frame to your robot's base frame (e.g., "base_link")

This will show your robot with all its links and joints. If you have joint states being published, you'll see the robot move according to those joint positions.

```xml
    <plugin name="gazebo_ros_control" filename="libgazebo_ros_control.so">
      <robotNamespace>/simple_arm</robotNamespace>
      <robotSimType>gazebo_ros_control/DefaultRobotHWSim</robotSimType>
    </plugin>
  </gazebo>

  <!-- Joint state publisher for Gazebo -->
  <gazebo>
    <plugin name="joint_state_publisher" filename="libgazebo_ros_joint_state_publisher.so">
      <jointName>shoulder_pan_joint, shoulder_lift_joint, elbow_joint, wrist_joint</jointName>
    </plugin>
  </gazebo>

</robot>
```

### Example 3: Xacro Macros for Symmetric Limbs

For humanoid robots, you often need symmetric left and right limbs. Here's how to use Xacro to create them efficiently:

```xml
<?xml version="1.0"?>
<robot name="humanoid_with_macros" xmlns:xacro="http://www.ros.org/wiki/xacro">

  <xacro:property name="M_PI" value="3.14159265359"/>

  <!-- Macro for a generic limb -->
  <xacro:macro name="arm_limb" params="side parent_link position">
    <joint name="${side}_shoulder_pan_joint" type="revolute">
      <parent link="${parent_link}"/>
      <child link="${side}_shoulder_link"/>
      <origin xyz="${position}" rpy="0 0 0"/>
      <axis xyz="0 0 1"/>
      <limit lower="${-M_PI/2}" upper="${M_PI/2}" effort="100" velocity="1.0"/>
    </joint>

    <link name="${side}_shoulder_link">
      <inertial>
        <mass value="0.5"/>
        <origin xyz="0 0 0.1"/>
        <inertia ixx="0.002" ixy="0.0" ixz="0.0" iyy="0.002" iyz="0.0" izz="0.001"/>
      </inertial>
      <visual>
        <origin xyz="0 0 0.1"/>
        <geometry>
          <cylinder radius="0.05" length="0.2"/>
        </geometry>
        <material name="blue"/>
      </visual>
      <collision>
        <origin xyz="0 0 0.1"/>
        <geometry>
          <cylinder radius="0.05" length="0.2"/>
        </geometry>
      </collision>
    </link>

    <!-- Additional joints and links for the rest of the arm -->
    <!-- ... -->
  </xacro:macro>

  <!-- Create both arms using the macro -->
  <xacro:arm_limb side="left" parent_link="torso" position="0.2 0.1 0.0"/>
  <xacro:arm_limb side="right" parent_link="torso" position="0.2 -0.1 0.0"/>

</robot>
```
